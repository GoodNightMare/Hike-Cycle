# 🏕️ HikeCycle

**HikeCycle** คือระบบ Web Application สำหรับบริหารจัดการการเช่าอุปกรณ์เดินป่า พัฒนาขึ้นเป็นโปรเจกต์เดี่ยว โดยเริ่มต้นจากการรับ Requirement จริงจากเพื่อนในสาขา และนำ Requirement ที่ได้รับมาวิเคราะห์ ออกแบบ และพัฒนาเป็นระบบตั้งแต่ Frontend, Backend ไปจนถึง Database

โปรเจกต์นี้เป็นหนึ่งในโปรเจกต์ที่ทำให้ได้ฝึกกระบวนการพัฒนาซอฟต์แวร์ตั้งแต่การทำความเข้าใจความต้องการของผู้ใช้ ไปจนถึงการพัฒนาระบบที่สามารถรองรับกระบวนการเช่าอุปกรณ์ได้

## 📌 เกี่ยวกับโปรเจกต์

HikeCycle ถูกออกแบบมาเพื่อช่วยจัดการกระบวนการเช่าอุปกรณ์สำหรับการเดินป่า โดยระบบรองรับผู้ใช้งานหลายระดับ ได้แก่ **User, Staff และ Admin** ซึ่งแต่ละ Role สามารถเข้าถึงและจัดการข้อมูลที่แตกต่างกันได้

ระบบครอบคลุมกระบวนการหลัก เช่น

* การจัดการสินค้า
* การจัดการ Stock
* การเลือกช่วงเวลาเช่า
* การเช่าอุปกรณ์
* การคืนอุปกรณ์
* การจัดการโปรโมชั่น
* การ Review สินค้า
* การจัดการสิทธิ์ผู้ใช้งาน

---

## ✨ Features

### 👤 User

ผู้ใช้งานทั่วไปสามารถใช้งานฟังก์ชันที่เกี่ยวข้องกับการเช่าอุปกรณ์ เช่น

* ดูรายการอุปกรณ์เดินป่า
* ดูรายละเอียดสินค้า
* เลือกช่วงวันที่ต้องการเช่า
* เช่าอุปกรณ์
* ดูโปรโมชั่น
* คืนอุปกรณ์
* Review สินค้า

### 🧑‍💼 Staff

Staff สามารถจัดการกระบวนการที่เกี่ยวข้องกับการให้บริการเช่า เช่น

* ตรวจสอบข้อมูลการเช่า
* จัดการการรับและคืนอุปกรณ์
* ตรวจสอบข้อมูลสินค้าและ Stock
* จัดการข้อมูลที่เกี่ยวข้องกับการให้บริการ

### 🛠️ Admin

Admin สามารถจัดการข้อมูลหลักของระบบ เช่น

* จัดการสินค้า
* จัดการ Stock
* จัดการโปรโมชั่น
* จัดการข้อมูลผู้ใช้งาน
* จัดการ Role และสิทธิ์ของผู้ใช้งาน
* ตรวจสอบข้อมูลการเช่าและข้อมูลภายในระบบ

---

## 📦 Product & Stock Management

ระบบรองรับการจัดการข้อมูลอุปกรณ์เดินป่าและจำนวนสินค้าใน Stock เพื่อให้สามารถตรวจสอบสถานะและจำนวนอุปกรณ์ที่พร้อมให้เช่าได้

ฟังก์ชันนี้เชื่อมโยงกับกระบวนการเช่าและคืนสินค้า เพื่อให้ข้อมูล Stock สอดคล้องกับสถานะของอุปกรณ์ภายในระบบ

---

## 📅 Rental System

ระบบรองรับกระบวนการเช่าอุปกรณ์ โดยผู้ใช้สามารถเลือกอุปกรณ์และกำหนดช่วงเวลาที่ต้องการเช่าได้

ข้อมูลที่เกี่ยวข้องกับการเช่า เช่น

* วันที่เริ่มเช่า
* วันที่คืน
* อุปกรณ์ที่ต้องการเช่า
* สถานะการเช่า
* สถานะสินค้า
* กระบวนการคืนอุปกรณ์

---

## 🎁 Promotion System

ระบบมีฟังก์ชันสำหรับจัดการโปรโมชั่น เพื่อรองรับการกำหนด Promotion สำหรับการเช่าอุปกรณ์

การพัฒนาส่วนนี้ช่วยให้ได้ฝึกการเขียน Business Logic ที่มากกว่าระบบ CRUD พื้นฐาน

## ⭐ Review System

ผู้ใช้งานสามารถ Review อุปกรณ์ผ่านระบบ เพื่อบันทึกความคิดเห็นเกี่ยวกับสินค้าที่ใช้งาน

## 🔐 Authentication & Role-Based Access Control

HikeCycle มีการแบ่งผู้ใช้งานออกเป็น 3 Role หลัก

```text
User
Staff
Admin
```

แต่ละ Role มีสิทธิ์ในการเข้าถึง Feature ของระบบแตกต่างกัน ทำให้ได้ฝึกการออกแบบ **Authentication และ Authorization** สำหรับ Web Application

## 🏗️ Architecture

ระบบพัฒนาตามแนวคิด **MVC (Model-View-Controller)** ของ ASP.NET Core

```text
            User
              │
              ▼
            View
              │
              ▼
          Controller
              │
              ▼
        Business Logic
              │
              ▼
            Model
              │
              ▼
         SQL Server
```

### Model

ใช้สำหรับกำหนดโครงสร้างข้อมูลและ Entity ต่าง ๆ ที่ระบบต้องใช้งาน

### View

ใช้สำหรับแสดง User Interface และข้อมูลให้กับผู้ใช้งาน

### Controller

ทำหน้าที่รับ Request จากผู้ใช้ ประมวลผล Logic และเชื่อมต่อระหว่าง View กับข้อมูลของระบบ

## 💡 สิ่งที่ได้เรียนรู้

### 1. Requirement Gathering

โปรเจกต์นี้ไม่ได้เริ่มต้นจาก Requirement ที่กำหนดไว้ทั้งหมด แต่เริ่มจากการพูดคุยและรับ Requirement จากเพื่อนต่างสาขาที่มีแนวคิดเกี่ยวกับระบบ

ทำให้ได้ฝึกการนำความต้องการของผู้ใช้มาวิเคราะห์และแปลงเป็น Feature ที่สามารถพัฒนาเป็น Software ได้จริง

### 2. การเรียนรู้ C# และ ASP.NET Core

HikeCycle เป็นโปรเจกต์ที่ได้เรียนรู้และนำ **C# และ ASP.NET Core MVC** มาใช้ในการสร้าง Web Application

ทำให้เข้าใจแนวคิดของ MVC และการเชื่อมโยงระหว่าง Frontend, Backend และ Database มากขึ้น

### 3. Full-Stack Development

เนื่องจากเป็นโปรเจกต์เดี่ยว จึงได้พัฒนาหลายส่วนของระบบด้วยตัวเอง ตั้งแต่ UI ไปจนถึง Business Logic และ Database

ทำให้ได้เห็นภาพรวมของการทำงานของ Full-Stack Application และความสัมพันธ์ระหว่างแต่ละส่วนของระบบ

### 4. Database Design

ได้ฝึกการออกแบบฐานข้อมูลสำหรับระบบที่มีข้อมูลหลายส่วน เช่น

* User
* Product
* Stock
* Rental
* Promotion
* Review

รวมถึงการออกแบบความสัมพันธ์ระหว่างข้อมูลให้สามารถรองรับการทำงานของระบบได้

### 5. Business Logic

ได้ฝึกการเขียน Logic ที่เกี่ยวข้องกับกระบวนการจริง เช่น

```text
เลือกสินค้า
    ↓
เลือกช่วงวันที่เช่า
    ↓
ตรวจสอบข้อมูล
    ↓
สร้างรายการเช่า
    ↓
จัดการสถานะสินค้า / Stock
    ↓
คืนอุปกรณ์
    ↓
อัปเดตสถานะ
```

ทำให้เข้าใจว่าการพัฒนา Web Application ไม่ได้มีเพียง CRUD แต่ยังต้องออกแบบ Logic ให้สอดคล้องกับกระบวนการใช้งานจริง
